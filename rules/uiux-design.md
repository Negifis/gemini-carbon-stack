# Frontend UI/UX & Live Browser Verification Rules

Эти правила активируются только при работе с фронтендом и пользовательскими интерфейсами:

1. **Никогда не выдавайте сгенерированную вёрстку за проверенный UI без запуска:** если в проекте есть локальный dev-сервер или статическая страница, запустите её и делегируйте живую визуальную и интерактивную проверку субагенту `browser` на `Gemini 4 Hydrogen` (`low`–`xhigh` по сложности UI через `swarm` + `Model="inherit"`, никогда не `Flash`), с верификацией по `BROWSER_HOST_FACTS`.
2. **Опирайтесь на существующую дизайн-систему проекта:** переиспользуйте токены цвета, типографики, отступов и компоненты проекта вместо введения произвольных одноразовых стилей.
3. **Проверяйте реальные пользовательские состояния:** пустое состояние (`empty`), загрузка (`loading`), ошибка (`error`), переполнение длинным текстом, клавиатурная навигация (`focus-visible`, ARIA-роли), контрастность и адаптивность (desktop + mobile viewport).
4. **Честность UI-текстов:** подписи кнопок, статусы и сообщения об ошибках должны точно отражать фактическое поведение системы, без декоративных заглушек под видом работающих элементов.
