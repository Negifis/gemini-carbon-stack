# Архитектура Gemini Carbon Engineering Stack

## 1. Среда исполнения и точки интеграции

Целевой хост — **Google Antigravity 2.0** (`Language Server hub-2.32.1`, CLI `agy 1.2.10`, ОС `Windows NT 10.0.26340.0`, нативный бинарник `carbon-stack.exe` на Rust, `Git 2.49`, внешний `codex-cli 0.160.0`). Автономный `gemini` CLI в системе не установлен, поэтому стек интегрируется напрямую в документированный контур плагинов и кастомизаций Antigravity:

- `~/.gemini/config/plugins/gemini-carbon-stack/` — атомарный плагин (включается автоматически при обнаружении Language Server без прямого редактирования приватного `~/.gemini/config/config.json`).
  - `rules/AGENTS.md` (`always_on`) — компактная глобальная конституция (~6.1 KB) без дублирования `SKILL.md`.
  - `rules/high-risk-verification.md` (`glob`) — строгие критерии и отпечатки SHA-256 для критичных путей и конфигов агента.
  - `rules/multi-agent-routing.md` (`model_decision`) — правила `swarm`, TTL prompt cache и маршрутизации `Claude`/`Codex`/`Neon`/`Hydrogen`.
  - `rules/engineering-tool-routing.md` (`model_decision`) — доменная маршрутизация к ленивым MCP/CLI-инструментам (code-graph, GitLab, UI/QA, AppSec, SRE/DB, 1С/Bitrix/Jira, диаграммы).
  - `rules/deep-audit.md` (`manual`) — глубокий ручной аудит и инварианты среды.
- `~/.gemini/config/rules/uiux-design.md` — контекстное правило (`trigger: model_decision`), автоматически подключаемое только для визуальных UI/UX-, дизайн-, layout/styling- и browser QA-задач.
- `~/.gemini/carbon-stack/` — изолированное хранилище runtime-состояния (`state/gate`, `state/continuity`, `state/memory`, `state/chips`, `state/hygiene`, `state/logs`) и резервных копий установщика (`backups/`).

## 2. Межмодельная маршрутизация и пропорциональность гейта

В Antigravity 2.0 для планирования и рутинных правок допустим координатор **`Orchestrator (Neon)`** (`gemini-pro-orchestrator-neon`, его Execution Mode выполняется на лёгком `gemini-flash-worker-agy`) либо **`Gemini 4 Carbon (High)`** (`gemini-4-carbon-high`), тогда как для сложной архитектуры, интеграции и фиксов по ревью Codex (`R1 -> R4`) используется прямой **`Gemini 4 Neon (High/XHigh)`** (`gemini-4-neon-high`/`gemini-4-neon-xhigh`). Дополнительно доступны модели семейства Claude (`claude-sonnet-5-5-high`, `claude-opus-5-5-high`), 4-уровневая линейка **`Gemini 4 Neon`** (`gemini-4-neon-{low,medium,high,xhigh}`), быстрая линейка **`Gemini 4 Hydrogen`** (`gemini-4-hydrogen-{low,medium,high,xhigh}`) и внешний OpenAI Codex CLI (`gpt-6.2-sol` на `medium` для `HIGH` и `gpt-6.2-astra` на `ultra` для `XHIGH`). Поскольку `invoke_subagent` принимает только Gemini-тиры, закрепление моделей Claude, `Gemini 4 Neon` и `Gemini 4 Hydrogen` выполняется через нативный инструмент `swarm` (при этом `Gemini Flash` запрещён и блокируется хуком `safety_guards.rs`):

1. **Пропорциональный риск (без эвристики `<= 3` строк):** уровень риска определяется типом затронутых компонентов, характером операции и опциональным контрактом `.agents/carbon-gate.json` (`default_code_risk`, `*_risk_globs`, `require_*_on_standard`). Обычные правки `STANDARD` требуют релевантных локальных проверок/тестов (`workspace_has_test_harness_opt`) и обязательного 1-линзового прохода `simplify-reviewer` (без автоматического adversarial-ревью); автономные статичные файлы/аддоны без тест-харнесса не требуют фиктивных тестов (но любая упавшая запущенная проверка блокирует закрытие).
2. **Обязательный Simplify (фиксированные линзы Claude в `plugin/agents/simplify-*.md` через `swarm`):** запускается на **`Claude Sonnet 5.5 (High)`** (`claude-sonnet-5-5-high`) с каузальным фоллбэком при подтверждённой ошибке/0% квоты на **`Gemini 4 Neon (XHigh)`** (`gemini-4-neon-xhigh`) и далее на **`Gemini 4 Hydrogen (XHigh)`** (`gemini-4-hydrogen-xhigh`; нативный `invoke_subagent(..., Model="inherit")` разрешён лишь при отказе всех 3 уровней роя). `PreToolUse` (`safety_guards.rs`) проверяет приоритет модели и автоматически инжектирует через `overwrite` дословный фиксированный промпт Claude + маркер `[FIXED_SIMPLIFY_LENS: <lane>]` — для `STANDARD` один воркер `simplify-reviewer`, для `HIGH`/`XHIGH` один параллельный прогон 3 воркеров (`simplify-reuse`, `simplify-quality`, `simplify-efficiency`) ДО 1-го раунда ревью. Проход привязан к кандидату (применение правок `simplify` не запускает цикл повторного `simplify`), требует закрытия воркеров (`swarm kill`) и жёстко проверяется на `Stop` и перед 1-м раундом `codex-lane review`.
3. **Внешнее adversarial-ревью (`HIGH`/`XHIGH` или opt-in проекта):** `carbon-stack codex-lane review` (OpenAI Codex CLI; конечный линейный контур `Finite Gate` без циклов сброса: `MAX_ORDINARY_REVIEW_ROUNDS = 4`, `MAX_CLOSURE_PASSES_PER_CYCLE = 2`): обязательный `simplify` в 3 линзы ДО ревью, затем `1..4` обычных раунда ревью в одной сессии через `codex exec resume <session_id>` с передачей компактной дельты (`interdiff`) и `ANTI-BOOMERANG LEDGER`, где `VERDICT: APPROVED` мгновенно закрывает гейт; при `Round 4: ESCALATE` выполняется 1 сфокусированный проход исследования и затем до `2` проходов `--closure` (`CLOSURE_VALIDATION: READY` -> `[gate] verified` / `pr-ready`; 2-й `CLOSURE_VALIDATION: BLOCKED` всегда завершает задачу терминальным `[gate] draft-blocked`).
4. **Внутреннее adversarial-ревью и TTL-маршрутизация раундов (`carbon-stack swarm-cache`):** при открытом circuit breaker Codex или прямом внутреннем ревью запускается на **`Claude Opus 5.5 (High)`** (`claude-opus-5-5-high`) с автоматической эскалацией при ошибке или 0% квоты Opus на **`Gemini 4 Neon (XHigh)`** (`gemini-4-neon-xhigh`, движок `internal-neon`, только для `HIGH`) либо на **`Gemini 4 Carbon (High)`** (`gemini-4-carbon-high`, обязателен для `XHIGH`). Поскольку upstream prompt cache Anthropic в Antigravity имеет 5-минутный ephemeral TTL (`300s`, безопасный порог `270s`), `carbon-stack swarm-cache prepare` направляет следующий раунд в тот же чат (`post_message`) только пока кэш тёплый (`<= 270s`), а при истечении TTL завершает раздутый чат (`kill`) и запускает `<name>-r<N>` с инкрементальным диффом и списком прошлых замечаний.
5. **Специализированные роли роя (`Neon` + `Hydrogen`):** `Gemini 4 Neon` (`low..xhigh`) ведёт сложную разведку, глубокую отладку, архитектуру, UI и тесты (`code-explorer` и профильные swarm-воркеры с изолированным владением путями); **`Gemini 4 Hydrogen`** (`low..xhigh`) закрывает быстрые и механические роли (`browser`, `translator`, быстрые скауты, простые параллельные билдеры) вместо запрещённого `Gemini Flash`. Плагин поставляет `8` субагентов (`adversarial-reviewer`, `adversarial-reviewer-xhigh`, `simplify-reviewer`, `simplify-reuse-reviewer`, `simplify-quality-reviewer`, `simplify-efficiency-reviewer`, `code-explorer`, `translator`) и `25` прогрессивных навыков.

## 3. Поток событий Lifecycle Hooks (`hooks.json` -> `carbon-stack hook`)

| Событие Antigravity | Подключённые модули (`rust/src/`) | Назначение и контракт ответа (protojson) |
|---|---|---|
| `SessionStart` | `continuity_hook.rs` (+ auto-heal в `installer.rs`) | Регистрация сессии, проверка совместного владения worktree (`tree_locks`), краткое восстановление из `handoff.json`/`CHECKPOINT.md` при `resume`/`compact` или активном незавершённом worktree (без авто-дампа памяти на чистых стартах) -> `{"injectSteps": [...]}` |
| `PreInvocation` | `continuity_hook.rs`, `chip_hooks.rs`, `cwg_pre_invocation.rs` | Детекция сильных коррекций пользователя и сжатия контекста (`compaction` -> `build_repo_handoff` <= 900 символов), доставка уведомлений о готовых чипах и 1-строчной сводки гейта только для `HIGH`/`XHIGH` (или opt-in) -> `{"injectSteps": [...]}` |
| `PreToolUse` | `safety_guards.rs`, `comment_density_guard.rs`, `continuity_hook.rs`, `cwg_mark.rs` | Защита от голого `git worktree remove` и `git reset --hard`, защита от вложенных субагентов, запрет `Gemini Flash`, инжекция активных ограничений `handoff`/`checkpoint` в промпт субагента (`safety_guards.rs`), контроль плотности комментариев при `edit_file`/`write_file` с лимитом 2 блокировки на файл (`comment_density_guard.rs`), Loop Guard на `read_file\|run_command` (`continuity_hook.rs`), снимок git и bounded non-git директорий для shell-команд (кроме `READ_ONLY`/`BOOKKEEPING`) (`cwg_mark.rs`) -> `{"decision": "allow"\|"deny", "overwrite": ...}` |
| `PostToolUse` | `cwg_mark.rs` | Сброс поколения Loop Guard после правок и `MUTATING`-команд (без срабатывания на `read_file`), запись фактического прогона проверок/тестов (`checks/*.jsonl`), 5-состояний классификатор shell (`READ_ONLY`, `BOOKKEEPING`, `VALIDATION`, `UNCERTAIN`, `MUTATING`) + измеренная дельта снимков (0-дельта `UNCERTAIN` не открывает `OPERATIONAL`), SHA-256 `content_marks` -> `{}` |
| `Stop` | `continuity_hook.rs`, `chip_hooks.rs`, `cwg_stop.rs` | Пост-коррекционный Output Lint, проверка сдачи дочернего чипа, пропорциональная финальная проверка Code Work Gate и независимого вердикта (`APPROVED` / `CLOSURE_VALIDATION: READY`) для `HIGH`/`XHIGH`/opt-in -> `{"decision": "allow"\|"continue"}` |

## 4. Происхождение доказательств (Zero Self-Attestation)

`cwg_stop.rs` не доверяет утверждениям модели в её собственном ответе:
1. **Тесты и проверки:** подтверждаются записями `PostToolUse` (`error == ""`) в `state/gate/checks/<session>.jsonl` с временной меткой не старее последней правки файлов.
2. **Внешнее ревью Codex:** подтверждается посессионным и пошаговым (`turns`) сканированием rollout-файлов `~/.codex/sessions/**/rollout-*.jsonl`, где каждый раунд (включая дописанные в тот же файл ходы `codex exec resume`) привязан к своему токену `REVIEW_ID`, `created_ts` из `state/gate/packets/` и проверке модели `gpt-6.2-astra` + `effort` уровня `ultra` (допускаются `ultra|xhigh|max` в `turn_context`) для `XHIGH` (`gpt-6.2-sol` на `medium` остаётся на `HIGH`).
3. **Внутреннее ревью Opus -> Neon/Carbon:** подтверждается системными файлами Language Server `<brain>/<convId>/.system_generated/swarm/members.json` (фактическая модель воркера), `board.jsonl` (фильтрация строго `post.agent == member_name`, исключающая эхо промпта координатора) и транскриптами самих воркеров. Одобрение от `gemini-4-carbon-high` (или `gemini-4-neon-xhigh` для `HIGH`) принимается только при наличии системного свидетельства ошибки или нулевой квоты `claude-opus-5-5-high`.
4. **Инвалидация после правок:** любое изменение байтов затронутых файлов после запуска ревьюера меняет SHA-256 в `content_marks` и делает прежний `APPROVED` недействительным.

## 5. Реальные границы гарантий

- Хуки Antigravity выполняются синхронно с таймаутом и работают в режиме fail-open при повреждении входного JSON или системном сбое (с записью в `hook-errors.jsonl`).
- При системных причинах остановки (`USER_CANCELED`, `ERROR`, `MAX_INVOCATIONS`, `MAX_TOKEN_BUDGET_EXCEEDED`) `Stop`-хук возвращает `allow`.
- Общая долговременная память между инструментами (Gemini / Claude / Codex) работает через установленный мост `nlm-memory` (`C:\Users\in\.local\bin\nlm-memory.CMD`), а локальное хранилище SQLite WAL + FTS5 (`carbon-stack carbon-memory`) служит быстрым офлайн-зеркалом с экспортом пакетов `export-nlm`.
- Миграция файловых локов `v1 <-> v2` в `<stack_home>/state` выполняется двухфазно под `_inst_mutex` и `.v2_alive.lease` (`LOCK_EX`): при откате `v2 -> v1` и перед копированием `v1 -> v2` фиксируется `.lock_epoch = "v1"` (единый протокол `O_EXCL` под `LOCK_SH` без `.swap`), а при установке очистка `.lock_epoch` выполняется атомарно внутри `LOCK_EX` после подтверждения отсутствия активных локов и процессов `v1` по `exe`/`cwd`/`cmdline` на Windows, Linux и macOS (`quiesce_and_clear_v1_lock_epoch`; параллельный запуск немодифицированных внедеревных процессов `v1` мимо установленного плагина в steady-state `v2` не поддерживается, а посмертные артефакты `v1` восстанавливаются через `.swap` + журнал причинности `.undo`).
