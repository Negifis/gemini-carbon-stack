# Multi-Agent & Swarm 2.0 Routing Rules

1. **Запрет `Gemini Flash` и асимметричная матрица Swarm 2.0:** никогда не передавайте `Model="flash"`, `flash_lite` или `gemini-3.8-flash-*`.
   - **Координатор:** `Orchestrator (Neon)` (`gemini-pro-orchestrator-neon`) — планирование, владение файлами, слияние, гейт.
   - **Механические/быстрые роли и стандартная разведка:** `Gemini 4 Hydrogen` (`-low` / `-medium` / `-high` / `-xhigh` — `browser`, `translator`, `gitlab-delivery-analyst`, стандартные скауты и простые `Disjoint Builders`).
   - **Сложная разведка, отладка, SRE, UI и тесты (`Gemini 4 Neon` `low..xhigh`):** `-low` (массовый синтаксис/схемы), `-medium`/`-high` (`test-author`), `-high`/`-xhigh` (`frontend-ui-builder`, `repo-architect-scout`, `infra-sre-diagnostician`, сложные `Disjoint Builders`), `-xhigh` (`root-cause-debugger` и primary fallback для `simplify`).
   - **Simplify:** `Claude Sonnet 5.5 High` (`SIMPLIFY_LENS: ALL` Fast-Path при `<= 2` файлов и `<= 30` строк; иначе 3 параллельные линзы; fallback — `gemini-4-neon-xhigh`, вторичный резерв — `gemini-4-hydrogen-xhigh`, никогда Carbon).
   - **Логика и безопасность (Прагматичный приоритет бизнес-намерения):** `carbon-stack codex-lane review --intent "..."` (`gpt-6.2-sol` на `high` для `HIGH`; `--xhigh` на `gpt-6.2-astra` для `XHIGH`; при подтверждённом сбое Codex — `claude-opus-5-5-high` -> `gemini-4-neon-xhigh` для `HIGH` или `gemini-4-carbon-high` для `XHIGH`). Блокируют только дефекты Класса A (`CRITICAL`/`HIGH` с `PRESERVES_INTENT: YES`); замечания Класса C/D (конфликт с целью, риск бизнес-модели, вкусовщина) отклоняются через `carbon-stack codex-lane dispose` и не возвращаются.
   - **UI/UX и дизайн-ревью *(строго только для UI/дизайн-задач)*:** `frontend-ui-builder` (`modern-web-guidance-plugin` + `mobbin`/`mobbin_mobbin` + `frontend-design`/`critique-*`) → скриншоты (`browser`/`playwright`/`chrome-devtools`) → независимые read-only ревьюеры (`visual-qa-reviewer` или `visual-design-critic` + `ux-adversarial-auditor`) с явным веб-поиском (`search_web`/`exa`/`tokenade search`) и `mobbin_mobbin` до `VISUAL_REVIEW_VERDICT: APPROVED`.
2. **Авто-проброс плагинов, скиллов, MCP и веб-доступа в брифы:** при спавне любого swarm-воркера или субагента координатор **самостоятельно** (без напоминания пользователя) перечисляет в брифе релевантные домену плагины, MCP-серверы, скиллы, исходный `BUSINESS_INTENT` и разрешённый read-only веб-поиск (`search_web` / `exa` / `tokenade search`).
3. **Владение файлами (`File Ownership Guard`):** перед параллельной разработкой разделите файлы через `carbon-stack swarm-ctl ownership set --worker <name> --paths <globs>` (либо `worktree create` при пересечении модулей/тестов, либо `workspace: "share"`/`"branch"` / `carbon-stack chip-handoff open`). Интеграция принадлежит координатору.
4. **Тёплый пул (`Warm Pool`), `Pointer-on-Board` и `Cursor Guard`:** будите живых `waiting` ревью-/билдер-воркеров через `post_message` `@mention` вместо холодного респавна, а simplify-воркеров завершайте пакетным `kill` сразу после единственного прохода перед ревью (`MAX_SIMPLIFY_PASSES = 1`). Объёмные отчёты сохраняйте в `.swarm/artifacts/<worker>-<round>.md` (`<= 12` строк + путь на доске). При `> 15` сообщениях передавайте `read_board(since=<last_seen_id>)` (или `carbon-stack swarm-ctl board summary --since <id>`).
5. **Защита `swarm_wait` и `Stall Watchdog`:** никогда не вызывайте `read_board` и `swarm_wait` в одном ходе; при зависании `in_flight` воркера сверх `SWARM_STALL_TIMEOUT_SEC` (`240` с) перезапускайте только зависший воркер. Подробные шаблоны — в скилле `swarm-orchestration`.
6. **Делегирование `browser` с не-Hydrogen координатора:** запустите `swarm` воркер с `model="gemini-4-hydrogen-<level>"`, который вызовет `invoke_subagent(TypeName="browser", Model="inherit")`; проверяйте результат строго по `BROWSER_HOST_FACTS`.
